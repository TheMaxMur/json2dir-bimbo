# bimbo-lang 0.1 — language reference 💅

Этот язык имеет одну практическую задачу: реализовать json2dir. Фронтенд
компилирует программу в LLVM IR, затем Clang собирает исполняемый файл.

## Грамматика

```ebnf
program   = { global | function } ;
global    = "glam" name ":" type "=" literal ";" ;
function  = "bestie" name "(" [ params ] ")" "->" return_type block ;
params    = name ":" type { "," name ":" type } ;
type      = "tea" | "yass" | "gloss" | "doll" ;
return_type = type | "ghost" ;
block     = "{" { statement } "}" ;
statement = "glam" name ":" type "=" expression ";"
          | name "=" expression ";"
          | "gimme" [ expression ] ";"
          | "vibecheck" expression block [ "whatever" ( block | statement_if ) ]
          | "strut" expression block
          | expression ";" ;
statement_if = "vibecheck" expression block [ "whatever" ( block | statement_if ) ] ;
```

Имена: ASCII-буквы и `_`, затем буквы, цифры и `_`. Ключевые слова и названия
типов зарезервированы. Комментарии начинаются с `//` или `💅`.

Точка входа строго `bestie main() -> tea`. Возвращаемое значение превращается
в 32-битный код выхода. `argc()` включает имя программы.

## Типы и выражения

- `tea` — знаковое 64-битное целое. Литералы десятичные, от
  `-9223372036854775808` до `9223372036854775807`. `+`, `-`, `*` и унарный `-`
  оборачиваются по модулю 2^64. `/` делит с усечением к нулю; `%` имеет знак
  делимого. Деление или остаток при нуле — runtime error. `INT64_MIN / -1`
  возвращает `INT64_MIN`, остаток равен 0.
- `yass` — логическое значение: `slay`, `flop`, `!`, `&&`, `||`. Оба бинарных
  оператора замыкаются коротко: правая часть исполняется только при необходимости.
- `gloss` — строка: UTF-8 байты и явная длина. Литералы используют JSON-экранирование
  (`\n`, `\uXXXX` и т.д.), допускают NUL. `+` конкатенирует строки;
  `==` и `!=` сравнивают все байты. Индексация и длина работают **в байтах**.
- `doll` — непрозрачный указатель на контейнер рантайма. Доступ только через
  встроенные функции; `==`/`!=` сравнивают идентичность объектов.
- `ghost` — отсутствие значения, допустимо только как тип результата функции.
  Возврат из такой функции: `gimme;` или конец тела.

Неявных преобразований типов нет. Сравнения `< <= > >=` допустимы только для
`tea`; `== !=` — для всех типов значений при одинаковых типах операндов.

Приоритеты от низкого к высокому: `||`, `&&`, `== !=`, `< <= > >=`, `+ -`,
`* / %`, унарные `! -`. Бинарные операторы левоассоциативны. Аргументы функций
вычисляются слева направо; скобки меняют порядок выражений.

## Переменные и функции

Все переменные изменяемые, всегда с типом и инициализатором. Локальные переменные
видимы в своём блоке после объявления. Внутренний блок может затенять внешнее
имя. Параметры и внешнее тело функции имеют общую область видимости. Глобальные
переменные видны всем функциям и инициализируются литералами `tea`, `yass` или
`gloss`; глобальная `doll` не поддерживается.

Функции могут вызывать друг друга до объявления, включая взаимную рекурсию.
Перегрузки нет. Все пути из функции с результатом должны иметь `gimme` или
прямой вызов `panic`. Цикл не считается доказательством возврата даже при
`strut slay`: после такого цикла для функции с результатом нужен fallback return.
Оператор сразу после прямого `gimme` или `panic` отклоняется как недостижимый.

```bimbo
bestie factorial(n: tea) -> tea {
    vibecheck n <= 1 { gimme 1; }
    whatever { gimme n * factorial(n - 1); }
}

bestie main() -> tea {
    spill("girl math: " + caption(factorial(5)));
    gimme 0;
}
```

## Встроенные функции

`ghost` ниже означает отсутствие результата. Неверный kind контейнера или
выход за границы вызывает runtime error с кодом 1.

| Функция | Результат | Действие |
|---|---|---|
| `spill(gloss)` | ghost | печать в stdout с переводом строки |
| `panic(gloss)` | ghost | `Error: ...` в stderr и завершение с кодом 1 |
| `argc()` | tea | число аргументов, включая имя программы |
| `sip()` | gloss | весь stdin; ошибка чтения или невалидный UTF-8 отклоняются |
| `length(gloss)` | tea | длина в байтах |
| `byte(gloss, tea)` | tea | байт 0…255 по индексу |
| `slice(gloss, tea, tea)` | gloss | диапазон `[start, end)` |
| `caption(tea)` | gloss | десятичная запись целого |
| `affordable(tea, tea, tea)` | yass | `(high * 10^9 + low)` после округления в double и масштабирования на `10^exponent` остаётся конечным |
| `lipstick()` | doll | пустой буфер байтов, kind 4 |
| `dab(doll, tea)` | ghost | добавить байт 0…255 в буфер |
| `sparkle(doll, tea)` | ghost | добавить Unicode scalar как UTF-8 |
| `reveal(doll)` | gloss | неизменяемая копия содержимого буфера |
| `closet()` | doll | пустая упорядоченная карта, kind 1 |
| `accessory(gloss)` | doll | строковый объект, kind 2 |
| `squad()` | doll | пустой вектор, kind 3 |
| `basic()` | doll | непрозрачное скалярное значение, kind 0 |
| `kind(doll)` | tea | номер kind |
| `size(doll)` | tea | число элементов карты, вектора или буфера |
| `dress(doll, gloss, doll)` | ghost | положить в карту; заменить повторный ключ |
| `invite(doll, doll)` | ghost | добавить элемент в вектор |
| `guest(doll, tea)` | doll | значение карты или вектора по индексу |
| `label(doll, tea)` | gloss | ключ карты по индексу в порядке UTF-8 байтов |
| `outfit(doll)` | gloss | значение строкового объекта |
| `unfollow(gloss)` | ghost | `unlink`; ошибки удаления игнорируются |
| `penthouse(gloss)` | ghost | `mkdir(0777)` с umask; EEXIST допускается |
| `catwalk(gloss)` | ghost | `chdir` в каталог |
| `backstage(gloss)` | ghost | `chdir("..")`; аргумент — контекст ошибки |
| `diary(gloss, gloss)` | ghost | создать/перезаписать файл с точными байтами |
| `heels(gloss)` | ghost | добавить биты исполнения `0111` к текущим правам |
| `situationship(gloss, gloss)` | ghost | создать симлинк: путь, цель |

Карта сравнивает ключи по байтам, с явной длиной и поддержкой NUL. Создание путей
и целей симлинков с NUL отклоняется. Пути файловых функций разрешаются относительно
cwd процесса, так что json2dir может спускаться в каталоги без накопления длинного
полного пути для каждого syscall.

`basic()` нужен парсеру json2dir для представления валидных JSON-чисел, bool и
null, которые недопустимы в схеме файлов. Их значения не сохраняются.

`affordable` принимает два неотрицательных limb для u64-significand:
`low < 10^9`, сумма не больше `UINT64_MAX`. Отрицательный exponent не может
переполнить double и может привести к нулю. Лексика числа, накопление significand,
пропуск лишних цифр и проверка exponent реализованы в `.bimbo`. Это сохраняет
порядок округления чисел стандартного `serde_json` из исходного проекта.

## Время жизни

Значения строк и контейнеров живут до завершения процесса. Буферы и контейнеры
растут геометрически, предыдущие выделения остаются в арене. Память арены
освобождается на выходе, включая `panic` и ошибки POSIX. `slice` разделяет память
с исходной строкой; `reveal` делает копию и не меняется при дальнейшем `dab`.

Этот подход рассчитан на короткую CLI-программу, которая читает один JSON.
Модулей, пользовательских структур, указателей, классов, исключений, break,
continue, потоков и сборщика мусора в версии 0.1 нет.
